# Краткий гайд по запуску hh-applicant-tool

## 🚀 Быстрый старт (TL;DR)

```bash
# 1. Склонировать и поставить зависимости
git clone https://github.com/it-ptitsa/hh-applicant-tool
cd hh-applicant-tool
python3 -m venv .venv
.venv/bin/pip install -e '.[playwright,pillow]'
.venv/bin/python -m hh_applicant_tool install      # Chromium для авторизации

# 2. Войти на hh.ru (введёшь код из SMS/почты)
.venv/bin/python -m hh_applicant_tool auth

# 3. Своё сопроводительное письмо — отредактировать
nano letter.txt

# 4. (опционально) AI для писем и ответов — вписать ключ, см. §6
.venv/bin/python -m hh_applicant_tool config -e

# 5. СНАЧАЛА проверка без отправки (--dry-run), потом убрать его для реальной рассылки
.venv/bin/python -m hh_applicant_tool apply-vacancies -L letter.txt -f \
  --search '(NAME:(frontend OR react OR typescript)) AND NOT NAME:(fullstack OR backend OR QA)' \
  --excluded-filter 'golang|\bgo\b|laravel|\bphp\b|bitrix|битрикс' \
  --apply-delay-min 40 --apply-delay-max 120 \
  --dry-run
```

Детали по каждому шагу — в разделах ниже. **Обязательно прочитай §15 «На что обращать внимание»** — там всё, на чём легко обжечься.

## 5. Рассылка откликов

```bash
.venv/bin/python -m hh_applicant_tool apply-vacancies \
  -L letter.txt \
  -f \
  --search 'ваш поисковый запрос' \
  --experience between1And3 \
  --excluded-filter 'junior|стажировк|intern|senior|lead'
```

### Ключевые параметры:

| Параметр                  | Описание                                                                        |
| ------------------------- | ------------------------------------------------------------------------------- |
| `-L letter.txt`           | Путь до файла с сопроводительным письмом                                        |
| `-f` / `--force-message`  | Всегда прикладывать письмо                                                      |
| `--search '...'`          | Поисковый запрос (язык HH: AND, OR, NOT)                                        |
| `--experience`            | Уровень опыта: `noExperience`, `between1And3`, `between3And6`, `moreThan6`      |
| `--area 1`                | Регион (1 = Москва, 2 = СПб; без параметра — все регионы)                       |
| `--excluded-filter '...'` | Regex-фильтр: пропускаем вакансии с такими словами в названии/описании          |
| `--dry-run`               | Пробный запуск без реальных откликов — полезно для проверки фильтров            |
| `--resume-id <id>`        | Откликаться только с конкретного резюме (по умолчанию — со всех опубликованных) |

### Пример для frontend middle по всем регионам:

```bash
.venv/bin/python -m hh_applicant_tool apply-vacancies \
  -L letter.txt \
  -f \
  --search '(frontend OR "frontend developer" OR react OR typescript OR next.js) NOT junior NOT intern NOT senior NOT lead NOT "team lead"' \
  --experience between1And3 \
  --excluded-filter 'junior|стажировк|intern|senior|lead|team\s*lead|bitrix|web3|crypto|blockchain|хакатон|конкурс'
```

> Лимит откликов на HH — **200 в сутки** на аккаунт. При достижении лимита утилита пишет `Достигли лимита на отклики` и продолжает обходить вакансии (сохраняет контакты), но не отправляет новые отклики.

## 6. Настройка AI (OpenRouter **или бесплатный Groq**) — один раз

AI нужен для двух задач:
- генерация сопроводительного письма под каждую вакансию (`apply-vacancies --ai`);
- ответы работодателям в чатах (`reply-employers --ai`).

Обе используют одну секцию конфига — `openai_cover_letter`. Провайдер на выбор:
**OpenRouter** (§6.1–6.2) или **Groq** (§6.2-альт) — Groq полностью бесплатен, бери его, если не готов платить.

### 6.1. Получить бесплатный ключ OpenRouter

1. Зайдите на **[openrouter.ai](https://openrouter.ai)** и войдите (через Google или GitHub).
2. Откройте **[openrouter.ai/settings/keys](https://openrouter.ai/settings/keys)** → нажмите **Create Key** → скопируйте ключ вида `sk-or-v1-...`.
3. Ключ показывается **только один раз** — сразу сохраните его.

> ⚠️ Никогда не вставляйте ключ в публичные места: README, чаты, скриншоты, коммиты. Если случайно засветили — отзовите его на той же странице и создайте новый.

### 6.2. Прописать ключ и модель в конфиг

```bash
.venv/bin/python -m hh_applicant_tool config -s openai_cover_letter.base_url https://openrouter.ai/api/v1/chat/completions
.venv/bin/python -m hh_applicant_tool config -s openai_cover_letter.model qwen/qwen3-next-80b-a3b-instruct:free
.venv/bin/python -m hh_applicant_tool config -s openai_cover_letter.api_key sk-or-v1-ВАШ_КЛЮЧ
.venv/bin/python -m hh_applicant_tool config -s openai_cover_letter.temperature 0.5
```

Бесплатные модели OpenRouter на выбор (вписываются в `...model`):
- `qwen/qwen3-next-80b-a3b-instruct:free` — хорошо с русским и инструкциями (рекомендуется);
- `moonshotai/kimi-k2.6:free` — пишет живее;
- `z-ai/glm-4.5-air:free` — полегче, как запасной.

> Бесплатный тариф ограничен (порядка **50 запросов/день**). Для больших рассылок пополните баланс OpenRouter (~$10) или возьмите платную модель.

### 6.2-альт. Бесплатная альтернатива — Groq (если не хотите платить)

[Groq](https://groq.com) даёт **бесплатный** OpenAI-совместимый API со щедрым дневным лимитом — отличный выбор, если не готовы пополнять OpenRouter.

1. Зайдите на **[console.groq.com/keys](https://console.groq.com/keys)** (вход через Google/GitHub).
2. **Create API Key** → скопируйте ключ вида `gsk_...` (показывается один раз).
3. Пропишите в **ту же** секцию конфига:

```bash
.venv/bin/python -m hh_applicant_tool config -s openai_cover_letter.base_url https://api.groq.com/openai/v1/chat/completions
.venv/bin/python -m hh_applicant_tool config -s openai_cover_letter.model llama-3.3-70b-versatile
.venv/bin/python -m hh_applicant_tool config -s openai_cover_letter.api_key gsk_ВАШ_КЛЮЧ
.venv/bin/python -m hh_applicant_tool config -s openai_cover_letter.temperature 0.5
```

> ⚠️ Лимиты Groq — **на аккаунт**, не на ключ (дневной лимит токенов). Для рассылки с одного аккаунта хватает. Если гоняете **2+ hh-аккаунта** под одним Groq-аккаунтом — лимит общий, упрётесь в 429: заведите отдельные Groq-аккаунты или возьмите платный план/другой провайдер.

### 6.3. Использование

Сопроводительные письма под каждую вакансию (промпт лежит в `cover_letter_prompt.txt` в корне проекта):

```bash
.venv/bin/python -m hh_applicant_tool apply-vacancies --ai -f \
  --system-prompt "$(cat cover_letter_prompt.txt)" \
  --message-prompt "Данные вакансии и резюме — ниже. Напиши письмо строго по правилам из системного промпта." \
  --search 'ваш поисковый запрос'
```

Ответы работодателям по чатам:

```bash
.venv/bin/python -m hh_applicant_tool reply-employers --ai
```

`reply-employers` пройдёт по активным чатам и ответит **только там, где последнее сообщение — от работодателя** (он реально что-то написал и ждёт ответа). Молчащим работодателям и непросмотренным откликам бот больше **не** пишет — анкеты (зарплата/график/тестовое) тоже пропускает на ручную обработку.

## 10. Конфиг — где хранится и как посмотреть

```bash
# Показать весь конфиг
.venv/bin/python -m hh_applicant_tool config

# Показать путь до файла конфига
.venv/bin/python -m hh_applicant_tool config -p

# Открыть конфиг в редакторе
.venv/bin/python -m hh_applicant_tool config -e

# Установить отдельное значение
.venv/bin/python -m hh_applicant_tool config -s proxy_url socks5h://127.0.0.1:1080

# Удалить значение
.venv/bin/python -m hh_applicant_tool config -u proxy_url
```

**Путь к конфигу зависит от ОС** (точный путь всегда покажет `config -p`):
- **Linux:** `~/.config/hh-applicant-tool/config.json`
- **macOS:** `~/Library/Application Support/hh-applicant-tool/config.json`
- **Windows:** `%APPDATA%\hh-applicant-tool\config.json`

Рядом с конфигом лежат `cookies.txt` (веб-сессия) и `data` (SQLite — история откликов, чёрный список).

## 13. Человекоподобные задержки между откликами

Чтобы рассылка не выглядела как бот (мгновенные отклики подряд), добавлены флаги случайной паузы **между откликами**:

```bash
.venv/bin/python -m hh_applicant_tool apply-vacancies -L letter.txt -f \
  --search '...' \
  --apply-delay-min 40 --apply-delay-max 180
```

- После каждого отправленного отклика — случайная пауза в диапазоне `[min, max]` секунд (каждый раз разная).
- В логе видно: `⏳ Пауза 73 сек перед следующим откликом`.
- По умолчанию `0` — без паузы (старое поведение).

**Как настроить под «живой» поиск:**
- Не отправляй 200 откликов залпом. Лучше `--apply-delay-min 40 --apply-delay-max 180` + несколько заходов в день по крону.
- Дефолтный `crontab` уже рассылает только с 8:00 до 21:00 — это тоже выглядит естественно.
- Пауза **случайная** (а не ровно 60с) — так менее палевно.

> Как это работает под капотом: утилита шлёт отклики через **API hh** (не «кликает» по страницам). Но при включённых `--excluded-filter` / `--ai-filter` / AI-письме она **догружает полное описание каждой вакансии** — то есть фактически «читает» её перед откликом.
>
> ⏳ **Поэтому с `--excluded-filter` рассылка идёт заметно медленнее** (десятки секунд на сотни вакансий — на каждую отдельный запрос к hh). Если на экране долго висит только «🚀 Начинаю рассылку…» — это **не зависание**, идёт обработка. Хочешь видеть прогресс по каждой вакансии — добавь `-vv`.

## 14. Фильтр нерелевантных вакансий и ревью чёрного списка

Поиск (`--search`) фильтрует **только по названию**. Чтобы отсеивать чужие стеки, указанные **в описании** (которых в названии не видно), используется `--excluded-filter` — regex по названию **и полному описанию**:

```bash
.venv/bin/python -m hh_applicant_tool apply-vacancies -L letter.txt -f \
  --search '(NAME:(frontend OR react OR typescript OR "next.js")) AND NOT NAME:(fullstack OR backend OR QA)' \
  --excluded-filter 'golang|\bgo\b|laravel|symfony|\bphp\b|wordpress|drupal|1с|bitrix|битрикс'
```

**🔑 Принцип фильтра:** исключай только **однозначные** стек-слова (`golang`, `php`, `laravel`…). НЕ исключай `vue`/`angular` — есть вакансии «React **или** Vue **или** Angular» (берут на любой стек, тебе подходят), и слово-фильтр их ошибочно выкинет. Различать «Vue-only» от «Vue/React» умеет только `--ai-filter heavy` (читает описание + твоё резюме по смыслу).

Полезные приёмы regex: `\bgo\b` ловит «Go», но не «Good»; `\bjava\b` не заденет «javascript»; регистр не важен.

### Цикл «ревью → тюнинг»

Все отклонённые фильтром вакансии сохраняются в базу — **с указанием сработавшего слова**. Периодически проверяй, не выкинуло ли хорошее:

```bash
.venv/bin/python -m hh_applicant_tool query \
  "SELECT name, employer_name, matched FROM skipped_vacancies WHERE reason='excluded_filter' ORDER BY created_at DESC LIMIT 30"
```

Пример вывода — сразу видно ошибку фильтра:
```
«Angular» ← Frontend-разработчик (Angular, React)   ← подходит! правь фильтр
«vue»     ← Frontend разработчик (Краснодар)         ← ок, это Vue-вакансия
```

Увидел ложное срабатывание → убери лишнее слово из `--excluded-filter`. Со временем фильтр сходится под тебя.

> Проверять фильтр без единого отклика можно через `--dry-run` — покажет, кого выкинуло.

## 15. ⚠️ На что обращать внимание (главное)

### Безопасность
- **API-ключи — только локально** (`config.json`, команда `config -e`). Никогда не коммить их в репозиторий, не вставляй в чат/скриншоты. Засветил — **отзови и создай новый**.
- `config.json`, `cookies.txt`, база `data` лежат **вне репозитория** (в каталоге профиля) — это правильно, не переноси их в git.

### AI-модель (для писем и ответов)
- **Бесплатные модели упираются в лимиты.** Groq и `:free`-модели OpenRouter в часы нагрузки отдают `429` и зависают на массовых запросах. Для надёжной рассылки — дешёвая **платная** модель (пополни OpenRouter на ~$10; письмо стоит доли цента) либо мирись с тем, что бесплатная иногда тупит.
- Ключ и модель задаются в секции `openai_cover_letter` (см. §6).

### Сопроводительное письмо
- Лучший режим — **адаптация твоего базового письма** (`letter.txt`) под вакансию, а не «написать с нуля». Меньше выдумок, сохраняется твой голос.
- Слабые модели **врут и путают факты** (приписывают чужой опыт, выдумывают стек). Поэтому в базовом письме не завязывайся на названия компаний, а перед массовой рассылкой **прогоняй `--dry-run`** и смотри пару писем.

### Фильтр вакансий
- `--search` фильтрует **только по названию**, `--excluded-filter` — по названию **и описанию**.
- **Не исключай `vue`/`angular`** по слову: вакансии «React **или** Vue» тебе подходят, а фильтр их выкинет. Исключай только однозначный чужой стек (`golang`, `php`, `laravel`…). Тонкие случаи — задача для `--ai-filter heavy`.
- **Периодически ревьюь чёрный список** (см. §14) — колонка `matched` покажет, по какому слову выкинуло хорошее.

### Поведение и лимиты
- **Лимит — 200 откликов в сутки** на аккаунт. Не шли залпом: ставь `--apply-delay-min/--apply-delay-max` (см. §13) и разбивай на заходы по крону.
- **Не вставляй ссылки** в сопроводительные — спам-фильтр hh может бросить в теневой бан.
- `--max-responses` **не работает** (баг) — ограничивай число через `--per-page`/`--total-pages`.

### Аккаунт и IP
- Рассылка с **домашнего IP** безопаснее, чем с сервера/датацентра.
- **Несколько аккаунтов с одного IP = баны.** Если гоняешь больше одного аккаунта (например, для нескольких человек) — каждому нужен свой прокси (лучше мобильный).

### Ответы в чатах (`reply-employers --use-ai`)
- AI отвечает **только на простые вопросы** по фактам из резюме. **Анкеты** (списки про зарплату, график, тестовое) он помечает и **оставляет тебе на ручную обработку**.
- Всё равно **проверяй ответы перед отправкой** — это живые работодатели. Важные чаты веди в интерактивном режиме (без `--ai`).

### Авторизация, капча, тесты
- Токен живёт ~2 недели и обновляется сам; иногда `refresh_token` истекает → нужна **полная авторизация заново**.
- Авторизация и решение капчи требуют **Playwright + Chromium** (`install`). Капча выводится в терминал (kitty/sixel) или решается Vision-моделью.
- Тесты к вакансиям решаются **эвристиками** (не гарантированно). Можно пропускать через `--skip-tests`.
- **⚠️ Две отдельные авторизации — API-токен и веб-сессия (cookies).** API-токен (для самих откликов) обновляется сам. Веб-сессия (cookies) нужна **только для вакансий с тестом и капчи**, живёт ~2 недели и **сама НЕ обновляется**. Многие свежие вакансии идут **с тестом** — если веб-сессия протухла, бот не сможет на них откликнуться.

> **🔴 Симптом: `Отправлено: 0`, хотя новые вакансии есть.**
> Частая причина — **протухла веб-сессия**, а свежая выдача забита вакансиями с тестами. Бот теперь пишет об этом прямо:
> `⚠️ Веб-сессия неактивна — вакансии с ТЕСТОМ пропускаю... authorize` и в конце `⚠️ Пропущено вакансий с тестом: N`.
> **Что делать:** проверь `test-session`; если ругается — переавторизуйся:
> ```bash
> .venv/bin/python -m hh_applicant_tool authorize
> ```
> Возьми в привычку переавторизовываться **раз в ~2 недели**. Не хочешь возиться с тестами — гоняй с `--skip-tests` (тогда тестовые вакансии просто пропускаются, но и откликов на них не будет).

### Прочее
- **Два разных хранилища настроек:** `config` (JSON-файл) и `settings` (таблица в БД). Не путай.
- **Лицензия оригинала — некоммерческая**, она запрещает публиковать изменённые версии кода. Помни об этом, если будешь что-то выкладывать.

### Золотое правило
> Перед любой массовой рассылкой — **`--dry-run`**. Он покажет, что улетит (письма, кого отфильтровало), не отправив ни одного отклика.

## 16. Анализ отказов и докрутка резюме (вручную)

Когда накопились отказы — можно понять, **что докрутить в резюме**, чтобы лучше проходить фильтры. Для этого есть скрипт:

```bash
.venv/bin/python analyze_rejections.py
# для другого профиля:
.venv/bin/python analyze_rejections.py --profile-id student1
```

Он показывает две вещи:

**1. Скорость отказов** — ключевой сигнал:
- **Быстрый отказ (минуты)** = сработал **автофильтр/ATS**, человек резюме не смотрел → тут помогут ключевые слова в резюме.
- **Медленный отказ (часы/дни)** = смотрел человек → резюме-твики почти не помогут (это конкуренция/решение рекрутера).

**2. Keyword-gap** — какие навыки требуют отказные вакансии, но которых **нет в твоём резюме**. Это кандидаты на добавление.

### Как действовать по результату
- 🟢 **Добавляй только то, что реально знаешь.** Скрипт уже отсеивает чужой стек, но если в подсказках вылез Angular/Vue/Backend — это шум, **не добавляй**.
- 🟢 **Лёгкие победы** — рабочие инструменты, которые ты точно используешь, но забыл указать: `Jira`, `Confluence`, `Адаптивная вёрстка` и т.п.
- 🟡 **Алиасы** — у hh поиск по строке: «WebSocket» не матчит «WebSockets», «Material UI» не матчит «MUI». Добавляй оба написания.
- ❌ **Не выдумывай** технологии ради фильтра — на собеседовании спросят.

### Куда добавлять
- **Навыки-теги** — лимит **30** (больше hh не примет). Если занято — выноси лишнее в «О себе».
- **«О себе»** — лимита почти нет: сюда можно вписать **развёрнутый категоризированный стек** (как у топ-резюме), он отлично индексируется нейропоиском.

> Резюме редактируется в веб-интерфейсе hh. Точечные поля (должность, навыки) ментор может править через API.

### Важная оговорка
Если **быстрых отказов почти нет** — значит резюме **уже проходит фильтры**, и докрутка даст немного. Тогда главный рычаг — не резюме, а **таргетинг** (релевантный фильтр вакансий, бан спам-работодателей).
