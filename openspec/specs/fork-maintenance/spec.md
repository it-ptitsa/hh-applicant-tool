# fork-maintenance Specification

## Purpose
Держать наш форк работоспособным и обновляемым: знать, чем он отличается от оригинала, не терять наши правки при слиянии и не публиковать личные данные в публичном репозитории.

## Requirements

### Requirement: Реестр наших отличий

Каждое поведение, которым форк отличается от оригинала, SHALL быть описано отдельным требованием в `openspec/specs/` и SHALL ссылаться на автотест, который это поведение проверяет.

#### Scenario: Новая доработка

- **WHEN** в форк добавляется правка, меняющая поведение относительно оригинала
- **THEN** в том же изменении появляется или обновляется требование в specs/ и тест на него

### Requirement: Слияние с оригиналом без потерь

Синхронизация с `upstream` SHALL выполняться в отдельной ветке. Перед переносом в `it-ptitsa` SHALL проходить все тесты, перечисленные в требованиях specs/; конфликт в файле с нашей правкой SHALL разрешаться сохранением обоих поведений, а не выбором одной стороны.

#### Scenario: Конфликт в apply_vacancies.py

- **WHEN** при слиянии возникает конфликт в файле, который затрагивает наше требование
- **THEN** после разрешения тесты этого требования зелёные, а изменения оригинала в том же месте сохранены

#### Scenario: Тихая потеря правки

- **WHEN** слияние прошло без конфликтов, но затёрло нашу правку
- **THEN** соответствующий тест из specs/ падает и слияние не переносится в it-ptitsa

### Requirement: Личные данные вне git

Репозиторий SHALL NOT содержать email, id резюме, тексты писем, токены ботов, куки и токены hh. Скрипты SHALL читать такие значения из файлов вне git (`apply.env`, `digest.env`, `letter.txt`, `config/`), для которых в репозитории лежат образцы `*.example`.

#### Scenario: Проверка перед коммитом

- **WHEN** в коммит попадает скрипт запуска
- **THEN** в нём нет почты, id резюме и секретов, а нужные значения берутся из env-файла по образцу

### Requirement: Сервер совпадает с веткой it-ptitsa

Рабочая копия на сервере SHALL NOT содержать незакоммиченных изменений отслеживаемых файлов. Правки кода SHALL попадать на сервер только через коммит в `it-ptitsa` и `git pull`.

#### Scenario: Ревизия сервера

- **WHEN** на сервере выполняется `git status`
- **THEN** изменённых отслеживаемых файлов нет; неотслеживаемые — только файлы вне git из списка выше, логи и бэкапы
