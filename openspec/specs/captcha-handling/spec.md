# captcha-handling Specification

## Purpose
Не обрывать рассылку откликов, когда API hh отвечает `captcha_required`.

## Requirements

### Requirement: Перенос кук после решения каптчи

После решения каптчи в браузере Playwright куки контекста SHALL переноситься в джар HTTP-сессии кликера независимо от типа джара (MozillaCookieJar/HHOnlyCookieJar или requests-джар). Отсутствие домена у куки SHALL NOT прерывать перенос. Проверяется `tests/test_captcha_cookies.py`.

#### Scenario: Джар сессии — MozillaCookieJar

- **WHEN** каптча решена и сессия использует HHOnlyCookieJar без метода `.set()`
- **THEN** куки переносятся через `set_cookie`, ошибки `'HHOnlyCookieJar' object has no attribute 'set'` нет

#### Scenario: Куки чужих доменов

- **WHEN** среди кук браузера есть домены не hh
- **THEN** HHOnlyCookieJar их отбрасывает, куки hh сохраняются

### Requirement: Каптча решается от имени аккаунта

Решение каптчи SHALL выполняться в браузерном контексте, в который загружены куки HTTP-сессии аккаунта, получившего `captcha_required`. Ответ SHALL считаться принятым только после ухода страницы с `/account/captcha`; повтор отклика SHALL выполняться только после подтверждённого успеха. При неверном ответе решатель SHALL запросить новую картинку и повторить попытку, не более 5 попыток. Опыт 30.09.2026: каптча, решённая в контексте с куками аккаунта, снимает блокировку — повтор отклика и следующий отклик проходят. Проверяется `tests/test_captcha_solver.py` и `tests/test_captcha_browser.py`.

#### Scenario: Правильный ответ

- **WHEN** API вернул `captcha_required` и каптча решена верно в контексте с куками аккаунта
- **THEN** страница уходит с `/account/captcha`, решатель возвращает успех, повтор того же отклика принимается API без новой каптчи

#### Scenario: Неверный ответ

- **WHEN** распознанный текст неверен и страница осталась на `/account/captcha`
- **THEN** решатель берёт новую картинку и пробует снова; после 5 неудач возвращает неуспех и повтор отклика не выполняется

#### Scenario: Куки аккаунта в браузере

- **WHEN** решатель открывает страницу каптчи
- **THEN** запрос страницы и отправка ответа несут куки сессии аккаунта

### Requirement: Распознавание каптчи hh

Распознавание SHALL использовать промпт под формат hh (два русских слова строчными по дуге, реальные, часто редкие словоформы) и SHALL нормализовать ответ: строчные буквы, ё→е, без кавычек и точек, одиночные пробелы. Лимит ответа модели SHALL быть достаточным для моделей с рассуждением (не менее 200 токенов). Модель задаётся в `openai_captcha.model` конфига; рекомендуемая на 30.09.2026 — `google/gemini-2.5-flash` (20/20 на размеченных каптчах против 5–6/10 у `gpt-4o-mini`).

#### Scenario: Ответ модели с кавычками и заглавными

- **WHEN** модель вернула `«Плюс Откозыряла.»`
- **THEN** в поле каптчи вводится `плюс откозыряла`

### Requirement: Проверка распознавания без откликов

Команда `check-captcha` SHALL прогонять вложенные в пакет образцы каптчи hh с известным ответом через модель из `openai_captcha` и SHALL NOT отправлять отклики или обращаться к API hh. При отсутствии `base_url`, `api_key` или `model` она SHALL называть недостающие ключи и печатать команды настройки; при неверном распознавании — рекомендуемую модель; код возврата 0 только если распознаны все образцы. Проверяется `tests/test_check_captcha.py`.

#### Scenario: Ученик не настроил каптчу

- **WHEN** ученик запускает `check-captcha` без секции `openai_captcha`
- **THEN** команда завершается с кодом 1 и печатает три команды `config -s openai_captcha.*`

#### Scenario: Настроено верно

- **WHEN** модель распознала все образцы
- **THEN** печатается «✅ Каптча настроена» и код возврата 0
