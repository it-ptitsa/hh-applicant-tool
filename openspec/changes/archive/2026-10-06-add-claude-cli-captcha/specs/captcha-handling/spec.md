## ADDED Requirements

### Requirement: Решатель каптчи оригинала

Решение каптчи SHALL идти одной сессией с аккаунтом, получившим `captcha_required` (решатель оригинала `api/captcha.py` `CaptchaFlow`, HTTP без браузера; браузерный транспорт — с куками аккаунта). Ответ SHALL отправляться только при согласии чтений (стратегия `consensus` по умолчанию: 5 чтений, порог 3) и считаться принятым только по однозначному сигналу hh; повтор отклика — только после принятия. Картинка по умолчанию запрашивается латиницей (`lang=en`). Проверяется тестами оригинала `tests/test_captcha_flow.py` и `tests/test_captcha_prompt.py`.

#### Scenario: Правильный ответ

- **WHEN** API вернул `captcha_required` и чтения картинки согласились
- **THEN** ответ отправляется той же сессией, hh его принимает, повтор отклика проходит

#### Scenario: Чтения не согласились

- **WHEN** голосов за лучший вариант меньше порога
- **THEN** ответ не отправляется, берётся новая картинка

### Requirement: Способ распознавания каптчи

Способ распознавания SHALL выбираться `openai_captcha.provider` (поверх общей секции `openai`): по умолчанию — OpenAI-совместимый API (рекомендуемая модель `google/gemini-2.5-flash` через OpenRouter); `claude-cli` — Claude Code CLI по подписке (`claude -p --model <claude_model>`, по умолчанию `opus`). Для `claude-cli` ответ SHALL приниматься только как два слова алфавита картинки; отказ, мусор, ненулевой код возврата, таймаут или отсутствие бинаря — неудачное чтение. При заданных `base_url` и `api_key` OpenAI-клиент SHALL служить запасным для `claude-cli`. Проверяется `tests/test_claude_cli_captcha.py` (настоящий подпроцесс с двойником `claude`).

#### Scenario: Подписка без ключа

- **WHEN** `provider = claude-cli`, ключа OpenRouter нет, claude вернул два слова
- **THEN** решатель получает ответ claude, запасного клиента нет

#### Scenario: Отказ модели при настроенном OpenRouter

- **WHEN** claude ответил отказом или не двумя словами
- **THEN** ответ берётся у OpenRouter

### Requirement: Проверка check-captcha

Команда `check-captcha` SHALL прогонять вложенные образцы каптчи с известным ответом через настроенный способ и SHALL NOT отправлять отклики или обращаться к API hh. Без настройки она SHALL печатать оба способа, первым — подписку Claude, если `claude` есть в PATH; для `claude-cli` без бинаря — сообщать об этом; при ошибках 402/429 — объяснять их. Код возврата 0 только если распознаны все образцы. Проверяется `tests/test_check_captcha.py`.

#### Scenario: Ученик с Claude Code без настройки

- **WHEN** секции каптчи нет, `claude` установлен
- **THEN** код 1, первыми напечатаны команды `provider claude-cli` и `claude_model opus`

#### Scenario: Настроено верно

- **WHEN** способ распознал все образцы
- **THEN** «✅ Каптча настроена» и код 0
