## Why

Ментору нужно каждый день видеть состояние рынка фронтенд-вакансий: сколько их всего, сколько
открылось с нуля, сколько работодатели переопубликовали и сколько ушло. Фильтр поиска hh
`period=1` этого не различает: 30.09.2026 из 40 вакансий «за сутки» только 19 были новыми,
21 — переопубликованные старые (медиана возраста 21 день, максимум 282). В выдаче поиска
`created_at` всегда равен `published_at`; дата первого создания есть только в детальной
карточке (`initial_created_at`). Анонимный доступ к API hh закрыт (403) — нужен токен.

## What Changes

- Новый скрипт `market_monitor.py` в корне репо (рядом с `chat_digest.py`, переиспользует его
  `load_token`, `Api`, `send_telegram`) и обёртка `market_monitor.sh` для крона хоста.
- Раз в день снимается снимок выдачи: фронт-слова в названии, Россия (`area=113`). Слова
  «верстальщик» и `next.js` в запрос не входят: первое 30.09 давало 79 вакансий полиграфии из 399,
  второе hh режет на `next`+`js` и цепляет Node.js-бэкенды. Реальный фронт — около 320 вакансий.
- Вакансии, опубликованные после прошлого запуска, делятся по `initial_created_at` на новые
  и переопубликованные. Вакансии из прошлого снимка, которых нет сегодня, — ушедшие; по
  детальной карточке ушедшие делятся на закрытые (архив/удалены) и выпавшие из выдачи.
- История хранится в SQLite `config/market.db` (вне git).
- Утренняя сводка в Telegram через `digest.env`: всего и дельта, Москва/СПб/удалёнка,
  новые/переопубликованные/ушедшие, топ работодателей среди новых, списки со ссылками.

## Capabilities

### New Capabilities
- `market-monitor`: ежедневный снимок рынка и сводка «новые / переопубликованные / ушедшие».

## Impact

`market_monitor.py`, `market_monitor.sh` (новые), `tests/test_market_monitor.py`.
Запросы к API hh идут токеном рабочего аккаунта: ~5 страниц поиска и несколько десятков
детальных карточек в день — меньше, чем один прогон кликера; отклики не отправляются.
